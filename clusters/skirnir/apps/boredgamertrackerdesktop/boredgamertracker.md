## Deployment (skirnir, `bg.aegirshus`)

Hosted as a Docker Compose stack at `clusters/skirnir/apps/boredgamertracker/`,
wired into the standard skirnir GitOps flow (`reconcile.sh` / `healthcheck.sh`,
`BOREDGAMERTRACKER_HOST=bg.${DOMAIN}` in Mímir's Well, routed by Caddy).

- `compose.yaml` — three services:
  - `web` — `nginx:1.27-alpine`, serves `./site` read-only, routed via Caddy
    at `bg.aegirshus` → `boredgamertracker-web:80`.
  - `api` — `python:3.12-alpine` running `api_server.py` (stdlib only, no
    deps) on :8080. Serves/saves the YouTube API key + handle so it can be
    entered once on the page instead of hand-edited over SSH. Caddy routes
    `bg.aegirshus/api/*` to this container, everything else to `web`.
  - `fetcher` — `python:3.12-alpine`, installs `pyyaml` on start, then loops
    `fetch_videos.py` + `sleep 1800` (every 30 min) forever. Mounts
    `fetch_videos.py` read-only and `./site` read-write.
- `nginx.conf` — sets `index comment-tracker.html` so `bg.aegirshus/` serves
  the page directly.
- `api_server.py` — `GET /api/config` returns `{apiKey, handle}`;
  `POST /api/config` writes them if the request's `password` field matches
  `APP_PASSWORD` (from `BOREDGAMERTRACKER_PASSWORD` in `.env` — blank in the
  committed `mimir.env.example`, must be set on the server). Writes to
  `site/key.json`.
- `site/` — the actual web root, kept separate from the repo/compose files so
  nginx doesn't serve `compose.yaml`/`fetch_videos.py`/this doc over HTTP:
  - `comment-tracker.html` — the main page. Single-file HTML/CSS/JS, sci-fi
    HUD theme (dark, teal/amber accents, Rajdhani + Inter fonts). No build
    step. On load, fetches `/api/config` for a default `apiKey`/`handle`
    (falls back to per-browser storage if that fails); the "Comment
    verification" panel has both "Save settings" (this browser only, no
    password) and "Save to server" (password-gated, persists via `api`).
  - `key.json` — written by `api_server.py`, **gitignored** (see
    `clusters/skirnir/apps/boredgamertracker/site/key.json` in `.gitignore`)
    — the API key never touches the repo.
  - `videos.yaml` — generated by `fetch_videos.py` at runtime, **gitignored**,
    survives `reconcile.sh`'s `git reset --hard` because it's untracked.
    Structure: `{ videos: [{id, title, published, thumb}, ...] }`.
- `fetch_videos.py` — fetches the channel's RSS feed
  (`https://www.youtube.com/feeds/videos.xml?channel_id=...`), merges new
  entries into `site/videos.yaml`, **never deletes old entries**. Runs inside
  the `fetcher` container now (was previously described as host cron — that
  changed when this moved into Compose).

## Security note on the API key

The key was always exposed to any visitor of the page anyway — it's used
directly in client-side `fetch()` calls to the YouTube Data API, visible in
browser devtools regardless of how it's stored. The password on `POST
/api/config` protects against a stranger *overwriting* your key (grief/DoS),
not against them *reading* it — same trust model as before, just adds
write-protection since the key is now server-persisted instead of purely
per-browser.

## Architecture (current, as of last session)

1. `fetch_videos.py` runs on a loop inside the `fetcher` container (every 30
   min), keeps `site/videos.yaml` in sync with YouTube, append-only.
2. The page loads `videos.yaml` via same-origin `fetch()` (no CORS proxy
   needed — this was the fix for an earlier problem, see "Known issues
   resolved" below) and parses it client-side with js-yaml (loaded from
   cdnjs).
3. Per-video state (`commented`, `verified`) is stored in the browser via
   `window.storage` (personal, not shared), keyed by YouTube video ID —
   independent of the video list, so it survives regardless of what's in
   `videos.yaml`.
4. Single reticle/checkmark per video:
   - empty = not marked
   - teal/filled = manually marked or marked via the Comment button
   - green = confirmed via the YouTube Data API (an actual comment from the
     user's channel was found)
5. "Comment" button: opens the video in a new tab, copies a random line
   from the user's editable comment-lines list to the clipboard (does NOT
   auto-post — auto-posting comments was explicitly ruled out as it
   violates YouTube ToS and undermines the giveaway; this stays manual).
6. Comment verification is fully automatic and server-side now:
   `fetch_videos.py`, on its normal 30-min loop inside the `fetcher`
   container, reads the API key/handle from `site/key.json`, resolves
   the channel ID once per run, and calls `commentThreads.list`
   (`order=time`, up to 3 pages / 300 most recent comments, matching on
   `authorChannelId.value`) for every video not already marked
   `commented: true` in `videos.yaml`. Once a video is confirmed, it's
   skipped on all future runs — bounds API quota use and it shrinks over
   time as more videos get confirmed. Confirmed videos show green
   automatically on load, no button or click needed. There is no
   client-side/manual verify path anymore (removed along with the old
   per-video "Verify via API" button) — right after a fresh upload there
   can be up to a ~30-min gap before the next fetcher cycle picks it up.
   Capped at 3 pages/300 comments — will report as not-yet-commented on
   very high-traffic videos if the comment is buried past that (known
   limitation).
7. Predefined comment lines: 100 Star Citizen jokes (user requested
   non-salty, joke-structured, affectionate-not-bitter tone) live in
   `DEFAULT_COMMENTS` array in the HTML, editable/resettable in the
   "Your comment lines" panel.
8. Manual paste-fallback panel ("Video database" section) still exists:
   lets the user paste raw feed XML/JSON for an immediate, browser-only
   preview if `videos.yaml` is missing or stale — does not write to the
   server file.

## Known issues resolved this session
- Originally tried live client-side fetching of the YouTube RSS feed via
  public CORS proxies (allorigins, corsproxy.io, thingproxy, r.jina.ai,
  rss2json) — ALL failed uniformly with "Failed to fetch" in Claude's
  artifact sandbox, which blocks outbound fetches to arbitrary domains.
  Solved by moving the fetch server-side (Python script + same-origin
  static file) instead of depending on browser-side CORS workarounds.
- YAML round-trip tested for titles containing colons, quotes, ampersands
  — PyYAML handles quoting correctly, verified locally.
